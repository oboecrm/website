# Code-first CRM for TypeScript teams

OboeCRM is an early open-source CRM project for teams that want their data model, APIs, and operational tooling to live in code.

This documentation is optimized for **technical evaluation**, not for exhaustive product admin walkthroughs. Start with the config model, understand the generated surfaces, and use GitHub to track the project as it hardens.

## Minimal config

```ts
// oboe.config.ts
import { defineConfig } from "@oboe/crm";

export default defineConfig({
  schema: {
    Account: {
      fields: {
        name: { type: "text", required: true },
        domain: { type: "text", unique: true },
      },
    },
    Deal: {
      fields: { value: { type: "currency" } },
      relations: { account: "Account" },
    },
  },
  api: { rest: true, graphql: true },
});
```

## What you get

- **Schema in code:** model accounts, deals, and custom objects in reviewed TypeScript.
- **Typed REST and GraphQL:** one schema, multiple interfaces for apps, workers, and integrations.
- **Admin UI:** an operator-facing layer that follows the same model as the API surface.
- **Self-hosting:** run inside your own infrastructure and keep data residency decisions in-house.

## Current scope

OboeCRM is still early. These docs focus on the **public shape and decision-making primitives** visible in the project today:

- config-driven schema
- generated API surfaces
- admin/runtime split
- access and extension points
- self-hosting expectations

Detailed low-level APIs that are not yet stable belong in [Roadmap](/docs/project/roadmap) and [Architecture](/docs/project/architecture), not in the main evaluation path.
