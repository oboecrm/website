# Contributing

Early OSS projects benefit from focused feedback more than broad feature wishlists.

## The most useful contributions

- clear issues about the config model
- feedback on naming and schema ergonomics
- critiques of the API and admin split
- implementation work aligned with the public direction

## Good first signal

If the project matches your stack and mental model, start with GitHub:

- star the repo
- open an issue with concrete use cases
- point out unclear docs or missing primitives

## Keep contributions grounded

Prefer feedback that ties back to one of these questions:

- does the config model hold up under real CRM use cases?
- do the generated surfaces feel predictable?
- does the self-hosted posture make operational sense?
