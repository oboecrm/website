# REST API

This page describes the role of the REST surface in OboeCRM's architecture.

## Purpose

REST is the most legible interface for predictable integrations, operational automations, and system boundaries where HTTP contracts matter more than query flexibility.

## Minimal shape

At a high level, the REST surface is intended to mirror the objects and constraints defined in the schema, so that records can be created, read, and updated without inventing a second model by hand.

## Good fit

- webhook consumers and producers
- integration pipelines
- stable CRUD-oriented flows
- systems that do not need GraphQL flexibility
