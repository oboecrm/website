# Overview

OboeCRM is aimed at engineering-led teams that want a CRM layer they can shape the same way they shape the rest of their stack: in code, through pull requests, with explicit interfaces.

This docs set is written for developers first. It assumes you care about:

- versioning schema changes in Git
- generating or standardizing API surfaces from one source of truth
- embedding or extending operational tooling without vendor lock-in
- self-hosting and infrastructure control

## How to read these docs

Read in this order if you are evaluating the project for the first time:

1. [Quickstart](/docs/getting-started/quickstart)
2. [Your first schema](/docs/getting-started/your-first-schema)
3. [Generated APIs](/docs/core-concepts/generated-apis)
4. [Config reference](/docs/reference/config-reference)
5. [Self-hosting](/docs/guides/self-hosting)

## What this documentation optimizes for

- **Fast evaluation:** you should know quickly whether the project fits your team.
- **Public contract first:** the docs emphasize the intended public surface over internal implementation details.
- **Honesty about maturity:** unstable areas are called out and moved out of the main path when possible.

## What these docs do not try to be yet

- a complete operator handbook
- a full REST or GraphQL schema dump
- a guarantee that every interface is frozen

For project direction and unresolved areas, see [Roadmap](/docs/project/roadmap) and [Architecture](/docs/project/architecture).
