# Admin UI

The admin UI is not the source of truth. It is a consumer of the source of truth.

That distinction matters because it changes how teams reason about ownership:

- engineers own the model in code
- operators use interfaces derived from that model
- customizations should not require a second, opaque configuration system

## What the admin layer should do well

- expose the current object model clearly
- make operational workflows legible
- respect access rules defined alongside the rest of the system

## What it should not replace

- schema review
- application-specific interfaces
- domain logic that belongs in code
