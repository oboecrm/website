# Events and hooks

CRMs become valuable when they connect system state to business action. Hooks and events are where that connection happens.

Examples of what teams typically want:

- trigger follow-up work when a deal changes stage
- sync records to downstream systems
- enrich CRM records with product or warehouse data

## Why this belongs in the core model

If hooks are bolted on later, teams end up with:

- duplicated business logic
- hidden automation builders
- integrations nobody can review confidently

A code-first system should make extension points explicit and versioned.
