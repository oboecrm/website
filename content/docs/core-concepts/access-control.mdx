# Access control

Access control is part of the product contract, not an afterthought.

In a code-first CRM, the value is that read and write expectations can be audited where the rest of the model is audited.

```ts
defineAccess({
  read: ({ user, record }) => user.role === "admin" || record.ownerId === user.id,
  write: ({ user }) => ["admin", "sales"].includes(user.role),
});
```

## Why colocating access matters

- reviewers see data model and permissions together
- application behavior is easier to reason about
- security posture does not depend on hidden admin toggles

## Common early cases

- owner-based record visibility
- role-based write access
- environment-specific restrictions for operational tasks
