# Installation

OboeCRM is positioned as a self-hosted, engineering-owned CRM layer. The installation story is therefore expected to feel closer to adopting application infrastructure than signing up for a hosted SaaS admin.

## What to expect

- a project-level config file
- an application runtime you deploy in your own environment
- a backing database you control
- environment variables for runtime and storage concerns

## What to verify early

Before going deep, confirm that your team actually wants these constraints:

- application code and CRM model in the same repository or delivery process
- ownership of schema changes and API evolution
- responsibility for hosting, secrets, and migrations

If that is attractive rather than a burden, OboeCRM is likely aligned with your operating model.

## Maturity note

As the project evolves, installation details may change faster than the core model. This docs set intentionally keeps the evaluation path focused on stable ideas first: schema, API surface, access, and deployment posture.
